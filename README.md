# Квитанция по квартплате — utilities frontend

ЛР-5, РИП 2026. Ветка `lab5-react-spa`. Отдельный гостевой SPA на React и
TypeScript. Источник карточек — **только `UTILITIES_MOCK`**. Работает без Go,
Docker и MinIO; фотографии и видео входят в Git.

Frontend: https://github.com/bar223/utilities-frontend.
Backend: https://github.com/bar223/utilities-backend.

## Запуск

Node.js: проверено с 26.13.0. После установки Node откройте новый PowerShell.
Точные версии зависимостей фиксируются `package-lock.json`.

```powershell
cd C:\lr-rip\utilities-frontend
npm ci
npm run dev
```

Открыть http://localhost:3000. Остановить — Ctrl+C. Если сервер уже работает
в фоне, второй запуск не нужен: порт фиксирован.

```powershell
npm run build
npm test
```

## Страницы, поля и кнопки

| Страница | Адрес | Содержимое и действия |
|---|---|---|
| Плитка коммунальных услуг | `/utilities` | Ползунок «Тариф до», выбранное значение, «Применить», карточки с фото, названием, тарифом и счётчиком лайков. Карточка открывает ленту по id. |
| Лента коммунальных услуг | `/utilities/feed`, `/utilities/feed/:id` | Видео, название, описание, тариф, норматив, единица, число лайков. «Следующая услуга» циклически переключает записи текущего списка. |

Корневой `/` переводит на плитку. Неизвестный маршрут/id даёт сообщение
со ссылкой возврата. Счётчик лайков информационный, не отправляет POST.

Нижнее меню: **Лента, Добавление, Плитка, Вход**. Активны только два пункта
просмотра; Добавление и Вход — disabled, как требует подробное задание ЛР-5.
Авторизация, POST и создание услуг через SPA относятся к ЛР-6.

## Фильтр тарифа

Ползунок 0–100 руб., шаг 1; 101 означает «не ограничен», поэтому отопление
с тарифом 2450 тоже доступно. Изменение ползунка меняет только подпись.
Список обновляется **после onSubmit/кнопки «Применить»**.

- 10 → электроэнергия и газоснабжение.
- 0 → сообщение о пустом результате.
- 101 → шесть услуг.

App хранит подтверждённый тариф; TariffFilter получает `appliedTariff` и
`onApply` через props и хранит редактируемый `sliderTariff`. Обе страницы
получают одинаковый отфильтрованный массив. «Следующая» не показывает
исключённые записи. Фильтр сохраняется при переходах SPA, сбрасывается при F5.

## Mock и fallback

Коллекция — `src/entities/utility/mock.ts`, тип `Utility` — `model.ts`.
У **«Капитального ремонта», id=6**, специально пустые `imageUrl` и `videoUrl`.

- Картинка по умолчанию: `/media/default-image.webp` — фото ЛЭП.
- Видео по умолчанию: `/media/default-video.mp4` — счётчик.
- Пустой source и ошибка загрузки обрабатываются в `UtilityMedia.tsx`.
- Файлы лежат в `public/media`, выдаются фронтендом, не MinIO.

Фото и видео предоставлены пользователем из `pics` для учебной демонстрации.

## Компоненты и все используемые хуки

| Компонент | Props / состояние | Хуки |
|---|---|---|
| App | appliedTariff; selectUtilities; props страниц | useState |
| TariffFilter | appliedTariff, onApply; sliderTariff | useState, useEffect |
| UtilityTilePage | utilities, appliedTariff, onApply | useEffect: document.title |
| UtilityFeedPage | utilities | useParams, useNavigate, useEffect |
| UtilityCard | utility | — |
| TabBar | активный маршрут | useLocation |
| UtilityImage / UtilityVideo | source, alt / poster, name | — |

Собственный Context, Outlet context и Redux не применяются. Данные идут через
props. React Router используется только для маршрутизации. StrictMode в dev
может дополнительно проверять эффекты; запросов API от этого не появляется.

Направление импортов следует принципам FSD из лекции 9: от app/pages к
features/entities/shared. Это небольшой учебный проект, а не полный FSD-шаблон.

## API и CORS

В ЛР-5 нет Fetch/XHR к API. В `vite.config.ts` подготовлен reverse proxy
`/api` → `http://localhost:8090` для ЛР-6; код его пока не вызывает.
Префикс /api сохраняется, потому что бэкенд уже использует его.
Отключать CORS расширением не нужно.

В Network видны JS/CSS, изображения, видео и WebSocket Vite. Требуется
отсутствие запросов API, а не отсутствие вообще всех сетевых запросов.

## Методичка и отчёт

Подробное задание требует два гостевых экрана с mock. Общая фраза «три
страницы и подключение API» противоречит этому уточнению; выполнено подробное
задание и порядок показа. Пример iTunes использует Outlet context, но общий
курс запрещает Context — в данной реализации обычные props.

Девять скриншотов: 1–2 страницы и Network; 3–4 fallback; 5–6 фильтр и props;
7–8 все хуки; 9 README. Руководство — `docs/lab5/screenshots.md`.
Снимки делает студент, в отчёте оставлены подписанные места.

Расчёт аппаратных требований на один лист входит в документацию. Pages,
PWA, Redux и пользовательские формы отнесены к следующим лабораторным.
