# ЛР-5 — как сделать девять скриншотов по макету отчёта

Файл для вставки: `C:\lr-rip\документы\Отчёт ЛР-5 — макет со скриншотами.docx`.
РПЗ отдельно: `C:\lr-rip\документы\РПЗ — Квитанция по квартплате — ЛР5.docx`.
Снимки делает студент. Вставляйте Win+Shift+S → Ctrl+V в соответствующую рамку.

## Подготовка

1. Фронтенд находится в **другом репозитории**: `C:\lr-rip\utilities-frontend`,
   ветка `lab5-react-spa`. Откройте эту папку в VS Code. Не путайте с backend.
2. Нужен Node.js (установлен). После установки откройте новый PowerShell.
3. Если приложение уже открывается на http://localhost:3000, повторно не запускайте.
   Иначе в PowerShell:

   ```powershell
   cd C:\lr-rip\utilities-frontend
   npm ci
   npm run dev
   ```

   Команда `npm ci` нужна после скачивания/смены зависимостей, не при каждом запуске.
4. Оставьте терминал с Vite открытым. Остановка — Ctrl+C.
5. Go, Docker, MinIO, Redis и токен для ЛР-5 не нужны: данные и медиа локальные.
   Никакие пароли вводить не требуется. Кнопки «Добавление» и «Вход» отключены намеренно.
6. Откройте макет отчёта в Word. ФИО и группа оставлены пустыми.
7. В Chrome F12 открывает DevTools. Ctrl+Shift+M включает эмуляцию устройства:
   обычно она не нужна — приложение само ограничено шириной 430 px.
   Для читаемости лучше широкий экран и DevTools справа.
8. Снимайте только нужную область. В кадре сохраняйте адрес и проверяемый результат.
   Для кода увеличьте масштаб VS Code Ctrl+плюс; не уменьшайте шрифт ради одного кадра.

## 1. Плитка с mock и Network

Откройте http://localhost:3000/utilities, F12 → **Network**.
Выберите **Fetch/XHR**, очистите журнал кнопкой перечёркнутого кружка и обновите
страницу Ctrl+R. Дождитесь загрузки карточек. Должно быть шесть услуг.

Снимите страницу с карточками, фильтром и нижним меню, адрес и Network с выбранным
Fetch/XHR. Здесь пустой журнал — правильный результат: API не вызывается.
При выборе All будут JS/CSS/фото/видео и WebSocket Vite, это нормально.

Вставить под «Скриншот 1». Подпись уже есть: плитка на mock без запросов API.

## 2. Лента с mock и Network

Откройте http://localhost:3000/utilities/feed/1. В Network выберите Fetch/XHR,
очистите журнал и обновите страницу. Должно воспроизводиться видео счётчика.
Если оно на паузе, нажмите Play. Звук по умолчанию отключён.

Снимите видео, название, тариф, описание, нижнее меню, адрес и Network.
Для демонстрации преподавателю нажмите стрелку вниз: меняется услуга без API.
Счётчик лайков здесь не кнопка и не отправляет POST.

## 3. Изображение по умолчанию

Откройте http://localhost:3000/utilities и обновите страницу: это сбросит фильтр.
Найдите «Капитальный ремонт», id=6. Вместо отдельной фотографии ремонта у него
видна фотография ЛЭП — локальный default-image.webp. Так сделано намеренно.

В VS Code Ctrl+P → `src/entities/utility/mock.ts`: у записи id=6 должны быть
`imageUrl: ''` и `videoUrl: ''`. Второй файл:
`src/shared/ui/UtilityMedia.tsx` — UtilityImage, выражение `source || DEFAULT_IMAGE`.
Путь DEFAULT_IMAGE находится в `src/shared/media.ts`.

Вставьте в рамку 3 изображение карточки и один-два читаемых снимка этого кода.
Не надо удалять файл в проекте, чтобы специально получить ошибку.

## 4. Видео по умолчанию

Откройте напрямую http://localhost:3000/utilities/feed/6, затем Ctrl+R.
Заголовок — «Капитальный ремонт», но играет видео электрического счётчика:
это default-video.mp4, поскольку в mock videoUrl пустой.

Снимите страницу. Для подтверждения: F12 → Elements, нажмите Ctrl+F и найдите
`default-video.mp4`; у video должен быть `src="/media/default-video.mp4"`.
Код — тот же UtilityMedia.tsx, функция UtilityVideo и `source || DEFAULT_VIDEO`.
Покажите файл `public/media/default-video.mp4` в дереве VS Code.
Оба подтверждения можно вставить в одну рамку 4.

## 5. Код фильтра

VS Code → Ctrl+P → `src/features/tariff-filter/TariffFilter.tsx`.
Снимите интерфейс Props, useState и функцию submit:
`preventDefault()` → `onApply(sliderTariff === 101 ? null : sliderTariff)`.
Вторым фрагментом при необходимости покажите Form onSubmit, Form.Range
value/onChange и Button type=submit.

Смысл для объяснения: ползунок хранит редактируемое значение в state; onChange
меняет подпись, а только submit передаёт подтверждённое значение родителю.

## 6. Props и применение фильтра

Откройте `src/app/App.tsx`: в кадре useState(appliedTariff), selectUtilities,
UtilityTilePage с props utilities/appliedTariff/onApply и UtilityFeedPage с utilities.
Функция фильтрации — `src/entities/utility/model.ts`, selectUtilities.

В браузере передвиньте ползунок на 10 (клик по ползунку, затем стрелки клавиатуры
помогают выбрать точное значение). До нажатия кнопки карточек всё ещё шесть.
Нажмите «Применить» — останутся электроэнергия и газоснабжение.
При желании добавьте этот результат рядом с кодом в рамку 6.

Объяснение: App передаёт данные вниз через props и callback onApply; setAppliedTariff
вызывает новый рендер. Лента работает по тому же отфильтрованному списку.
После последнего элемента «Следующая» возвращает первый. 101 снимает ограничение,
0 даёт пустое состояние. Обновление F5 сбрасывает state.

## 7. Все useState и useEffect

Покажите следующие места, а не только строки import:

| Файл | Место и назначение |
|---|---|
| `src/app/App.tsx` | useState: применённый тариф |
| `src/features/tariff-filter/TariffFilter.tsx` | useState: положение ползунка; useEffect: синхронизация с appliedTariff |
| `src/pages/utility-tile/UtilityTilePage.tsx` | useEffect с []: заголовок вкладки при монтировании |
| `src/pages/utility-feed/UtilityFeedPage.tsx` | useEffect с [utility]: заголовок вкладки при смене услуги |

Можно сделать 3–4 читаемых фрагмента и разместить их в рамке 7 последовательно.
Не сжимайте весь проект в один нечитаемый снимок. Рамка растянется по содержимому.
StrictMode в dev может повторно запускать эффект для проверки — это ожидаемо.

## 8. Все хуки React Router

Откройте `src/pages/utility-feed/UtilityFeedPage.tsx`. Снимите вызовы useParams,
useNavigate, поиск utility по id и функцию next с navigate.
Затем `src/widgets/tab-bar/TabBar.tsx`: useLocation и pathname в active/aria-current.

Подписи к фрагментам: «id из URL», «программный переход», «активная вкладка».
Вместе со снимком 7 это покрывает все используемые хуки. Собственные Context,
useOutletContext и Redux в проекте отсутствуют.

## После девяти снимков

- Удалить из макета служебные подсказки и пустые рамки, оставить изображения и подписи.
- Вписать ФИО/группу. Краткие ответы на контрольные вопросы уже есть в конце отчёта.
- В РПЗ вставить свои плитку и ленту в два отмеченных места раздела интерфейса.
- В Word обновить содержание: щелчок по нему → Обновить поле → целиком.
- Отдельно приложить одностраничный расчёт аппаратных требований.
- По требованию преподавателя распечатать один препринт и подписать перевод терминов.

## Частые проблемы

| Проблема | Решение |
|---|---|
| ERR_CONNECTION_REFUSED :3000 | запустить npm run dev и оставить терминал |
| EADDRINUSE | уже есть сервер; не запускать второй |
| В ленте id=6 «не найдено» | снять фильтр или открыть URL заново с Ctrl+R |
| В Network много запросов | выбрать Fetch/XHR; медиа/JS/CSS/WS не являются API |
| Не воспроизводится видео | нажать Play, проверить локальный src и обновить страницу |
| Вход/Добавление не работают | это disabled-пункты по заданию ЛР-5 |
| После F5 пропал фильтр | useState живёт в памяти, это ожидаемо для ЛР-5 |

Если отдельно понадобится проверить бэкенд ЛР-4: Swagger http://localhost:8090/swagger/index.html,
creator/123. Adminer http://localhost:8081 — PostgreSQL, сервер postgres,
пользователь postgres, пароль postgres, база utilities. MinIO http://localhost:9001 —
root/rootpassword. Эти сервисы не требуются ни для одного из девяти снимков ЛР-5.
